## ClawHub release procedure

Use `npm run skill:publish -- <version> "<what changed>"`, or the **Publish
ClawHub skill** workflow. Do not hand-run `clawhub skill publish`: the script
checks source version, source commit, cleanliness, pushed state, freshness and
whether the bundle actually changed. `--dry-run` previews it. Authenticate with
`npx clawhub@latest login` when required. Record the successful release in
`clawhub/published.json`; do not mark a prepared bundle as published.

Prices stay in the live menu, not in a static skill. Endpoint or behavior changes
can require a skill update even when the server remains reachable.

## Checks and evidence

`npm run listings:test` holds registry descriptors and host wrappers to source.
`npm run findability:check` walks the fixed-path [inventory](../scripts/lib/findability.mjs).
`npm run listings:check` reads public listings and registry versions without
rewriting the [baselines](../docs/listings/) unless explicitly run with `--record`.
Path presence, installed package behavior and marketplace acceptance are distinct.

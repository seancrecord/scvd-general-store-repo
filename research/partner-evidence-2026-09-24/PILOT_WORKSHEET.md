# One-workflow pilot worksheet

Prepared September 24, 2026. Template only: no agreed partner, no running
pilot, no assigned paid attempt. Fill the fields with the actual counterpart.

## Agreement

- Partner / reviewer / public contact route: **unassigned**.
- Product, endpoint URL, method and synthetic input: **unassigned**.
- Intended engineering/release/support decision: **unassigned**.
- Start / end date and natural repeat trigger: **unassigned**.
- Expected usable fulfillment and how to verify it: **unassigned**.
- Existing instrument and compatibility evidence: **unassigned**.
- Authorized paid attempt, spend cap, and stop owner: **none**.
- Shareable evidence / private fields / agreed retention: **unassigned**.
- Keeper-time allowance: propose eight hours; review scope at four.

## Baseline record

Preserve exact request, observation time, runtime/instrument version, response
status, challenge, limits, error, body digest, and permitted retained bytes.
Keep a signed original if produced; verify independently before calling it
verified. Distinguish quote, authorization, settlement, and delivery. Unknown
stages remain unknown; a terminal failure is not a license to retry payment.

## Cold preparation task — proposed, not executed

Give the agent the starting URL and this task, without the research findings:

> Determine whether this service can satisfy the stated task. Find the exact
> public product, price and cadence, request method and required inputs,
> payment requirements, expected output, and documented recovery route.
> Prepare the request and explain any uncertainty. Stop before payment,
> signing, session creation, account creation, or submission of private data.
> Use read-only tools. Do not install tools or ask for credentials. Report
> every guess, retry, missing input, and reason to decline.

Before a run fill in the actual buyer task, host/tool access, model/version,
entry point, time/request budget, and allowed public URLs. Run A starts at the
human product page; run B at the machine-facing document if one exists. Two
to four runs total; add a run only to answer a named question. A reader given
different tools/context is a different condition, not a replicate.

Capture every initiated run's transcript and outcome: completed, abandoned,
interrupted, or instrument failed. Every proposed request remains unexecuted
unless its own scope permits it. Existing research in this task is not a cold
run and must not be relabeled as one. Any future agent delegation needs the
applicable authorization; this file does not schedule or spawn agents.

## Partner response — a short reply is sufficient

1. Is the observation accurate, disputed, or unresolved?
2. Was it already known, and did you change anything or decide not to act?
3. Did it help a specific decision? Which one?
4. Would another bounded observation help? At what trigger?

Store these answers separately. A finding can be known, reproduced, fixed,
and useful at the same time. A partner-reported fix stays a claim until retest.

## Closing record

- Material observations delivered / reviewed / unreviewed.
- Reproductions attempted / reproduced / inconclusive, by each party.
- Repairs claimed / retested / passed; method changes listed separately.
- Instrument errors and corrections; unresolved disagreements.
- All run outcomes and paid-attempt stages, including skipped attempts.
- Keeper hours, other labor and actual money spent.
- Named decision use; repeat requested/agreed/completed; free versus paid.
- Continue, narrow or stop, with a reason and no implicit renewal.

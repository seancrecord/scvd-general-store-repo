# Evidence reuse brief — prepared, not sent

Use this alongside the existing [partner pilot plan](../../docs/PARTNER_EVIDENCE_PILOTS_2026-09.md),
starting with its Merit / x402scan / AgentCash workstream. Do not start another
parallel outreach campaign or characterize any prospect as a partner already.

## The useful unit to give a partner

A dated observation they can attach to one endpoint listing, support answer,
or issue: what SCVD observed, the exact endpoint and method, the original
evidence link, how to check it, and what it could not establish. It can report
a clean observation. A positive defect finding is not required.

Use [the corpus index](https://scvd.store/corpus.json) to find an original signed
snapshot, [the corpus](https://scvd.store/corpus) for human-readable context,
and [the defect definition](https://scvd.store/defects/offer-contradicts-challenge)
when that specific mismatch is present. A definition is not evidence that a
particular seller has the defect. Host summaries are unsigned views over
history; cite the original snapshot for the signed observation. Re-read the
current payload and published reuse terms before distributing a selected row.

The [Hugging Face publisher](https://huggingface.co/keeper-scvd) already appeared
in Google's dataset answer in this walk. Keep its link back to the original
evidence useful. This is a demonstrated discovery surface, not a promise that
another repository or directory will produce the same effect.

## Citation format for a real observation

> SCVD observed **[specific result]** for **[exact endpoint and method]** at
> **[observation time]**, within **[probe scope]**. Original evidence:
> **[snapshot URL and row identifier]**. Verification: **[the artifact's
> published verification instructions]**. Not observed or established:
> **[material gaps, including payment/delivery where not exercised]**.

This is an unfilled format, not a measured claim. Populate it from a real
artifact in the existing dossier before sending it. Do not replace observation
time with publication time or infer present availability from a historical row.
Keep methodology and correction links beside any shortened quotation.

## Concrete first integration

If the existing Merit discussion leads to a useful workflow, offer one optional evidence reference beside
the affected listing or issue. The reference opens the dated original and
discloses its bounds. The partner keeps its own eligibility/routing decision;
SCVD supplies evidence rather than a new score or certification badge.

Ask the reviewer to identify whether that evidence changes a listing,
documentation, support, or release decision. If it does, record the public
reuse URL and whether they request another observation. A backlink alone is
not adoption; a request to use the evidence again is stronger evidence.

Capture only what the arrangement authorizes: the selected public endpoint,
decision use, reuse URL, and repeat-use request. Client payloads, credentials,
identities and private buying histories are not part of this proposed packet.
Aggregate buying behavior is a later agreement, not implied by free tool use.

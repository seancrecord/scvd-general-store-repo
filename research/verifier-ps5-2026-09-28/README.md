# PS5 — JWS extension envelopes, September 28

Selected increment: accept the x402 `{ format: "jws", signature: compactJws }`
transport around the verifier's existing Ed25519/local revision-1 profile.
Source version 1.8.0 is prepared locally. This is not a registry publication
or an adoption/retention measurement. Buyer/model qualification remains deferred
per keeper direction; PS5 is not marked wholly complete.

## Why this combination

The [pinned official extension](https://github.com/x402-foundation/x402/blob/a9955ae5538e5531557405091910136a2a2864c8/specs/extensions/extension-offer-and-receipt.md)
defines this wrapper in section 3.1.1. SCVD already emits it from
`src/lib/offer-receipt.ts`; the independent matrix already retains labelled
JWS offer and receipt controls. The previous package rejected these objects
even when its existing verifier could validate the compact string inside.
Callers can now pass the artifact directly to the package APIs.

This is an observed integration mismatch, not evidence of outside demand or
third-party adoption. ES256, ES256K and EIP-712 remain unsupported. Their
independent vectors establish testability, not sufficient demand to select
new cryptography ahead of a wrapper already emitted and documented. This
increment adds no runtime dependency or crypto implementation and preserves
the existing key resolution and cryptographic checks. Further algorithms need
their own bounded selection. PS6 need not wait for the entire matrix.

## Exact scope

`verifyArtifact`, `verifyOffer` and `verifyReceipt` accept the envelope.
Offer `acceptIndex` must be a nonnegative safe integer when present. It remains
unsigned and is never used to claim agreement with payment terms. Receipt
indices and separate payloads are malformed. Unknown fields are unsupported;
wrapper-supplied keys and URLs are never trusted. Nested wrappers, detached
JWS, other algorithms and other envelope formats are not added.

The signed payload still receives the existing local revision-1 checks, with
their documented limits. Valid does not establish full extension conformance,
issuer authorization, settlement, delivery or permission to spend. CLI
`verify-source` and hosted API input contracts are not expanded by this change.

## Evidence

The full store regression passed: 835 files, 15,624 tests passed and one
skipped. Typechecking, bundle checks, independent-vector reproduction and
the evidence suite also passed. These are dated local results, not CI or
publication receipts.

[verification.json](verification.json) records runtime versions, source hashes,
commands and observed results; [sources.json](sources.json) pins the official
specification. The 23 new Node tests first failed on the unmodified verifier
and then passed with envelope support. Tampered payloads/headers/signatures,
wrong keys, unavailable keys, algorithm confusion, unsigned indices and
wrapper-selected key attempts are covered. Worker tests use native Ed25519;
the independent JWS oracle uses Node/OpenSSL against noble-generated bytes.

All 90 independent artifact values remain identical to the baseline. Only
current capability expectations and provenance changed: Ed25519 labelled
wrappers can verify; ES256/ES256K wrappers now reach unsupported-algorithm
reporting; an EIP-712 payload falsely labelled JWS is malformed. Historical
PS2/PS3 observations are not rewritten or rescored.

A fresh local tarball was installed offline with lifecycle scripts disabled.
All 24 installed package files matched source bytes. The retained
[JavaScript consumer](consumer.mjs) and [strict TypeScript consumer](consumer.ts)
each check valid, tampered, unsupported-algorithm and missing-key outcomes,
plus the new capability inventory and scope. They use synthetic fixture keys,
never live issuer requests or a model. Installation/compilation is separate
from model activation and public npm qualification.

To repeat the consumer check, pack `./verifier`, install that tarball in a new
ES-module project offline, and copy `consumer.mjs`, `consumer.ts` and
`tsconfig.json` beside its `node_modules`. Run `node consumer.mjs`, compile
with the repository's installed TypeScript compiler using that config, then
run `node dist/consumer.js`. `verification.json` records the exact tested
package version and tarball hash. Source commands:

```sh
node --test verifier/jws-envelope.test.mjs
npm test -- test/verifier-independent-vectors.spec.ts
npm run evidence:test
npm run verifier:vectors:check
npm run typecheck
npm run build:check
npm test
```

Release and model activation remain separate follow-through. No PR, commit,
publication, deployment, live payment or buyer qualification was performed
for this local implementation record.

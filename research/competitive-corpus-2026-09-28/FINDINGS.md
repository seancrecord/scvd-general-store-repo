cause of a mismatch, or which party should change its terms.

For 8 → 9, the 127 eligible pairs record repeated checks: {"bazaar-extension":3,"solana-rail-receivable":1,"status-402":13,"network-mainnet":2,"payment-required-header":1,"signed-offers":1}. Exclusions: {"method_not_recorded":4051}.

Eligibility requires a unique exact host/URL match, two valid increasing
per-host timestamps, a recorded unchanged method and battery, two ready/not_ready
verdicts and explicit failed-check arrays. Exclusions reconcile to the matched
denominator. Early rounds lacking methods or dates remain unusable for this
strict comparison; no retrospective GET assumption fills them.

This is a selected instrument cohort, not an industry failure rate. The same
battery label does not freeze every implementation detail, request body or
header. A transition describes recorded outcomes, not a proved repair or
regression cause. No uninterrupted uptime, repair duration or buyer impact can
be inferred between observations. Zero observed recovery in this cohort is not
evidence that no operators fixed anything.

## 4. A failed x402 reading does not establish absence of MPP

The latest snapshot records MPP spoken on 250 rows;
28 of those have an x402 not_ready verdict.
Treat these as separate protocol observations. Neither establishes payment or
delivery, and an x402-only filter would lose the protocol distinction.

## Reproduce and reuse

Run [the notebook](../../examples/corpus-recompute.ipynb) from a repository
checkout with Python 3 and Node 22. It fetches the compact index, preserves raw
snapshot bytes, authenticates the full chain with the existing verifier, and
prints these findings and denominators. The command-line equivalent is:

```sh
node scripts/corpus-findings.mjs SNAPSHOT_DIR PUBLIC_KEY_JSON OUTPUT_DIR
```

Use the existing [weekly brief](https://scvd.store/corpus/brief) and monthly
report as publication channels. These findings are prepared material, not a
new publication or a statement that a partner adopted them. Start with catalog
agreement, because its denominator and individual source rows are available.
Keep the stricter change cohort as a methodological note until it grows.

- Host rows are sampled endpoints, not every route or independent purchases.
- New snapshot time is not a new probe time. Missing row observation times and methods stay unknown.
- Same recorded battery is a comparability filter, not proof that every implementation detail remained identical.
- Failed checks are x402 battery outcomes; MPP-only endpoints can be x402 not_ready without an MPP defect.
- Repeated failure at two moments does not establish continuous failure, repair time, repair causation, or current state.
- Catalog comparison is the signed row’s recorded comparison, not a new comparison with a live directory.
- No payment, delivery, buyer behavior, market share, or Bitcoin timestamp verification is established.

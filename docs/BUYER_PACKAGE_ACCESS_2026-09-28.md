# Directed buyer package access — September 28

The [generated-report cohort](../research/generated-report-buyer-2026-09-28/REPORT.md) exposed a test-setup gap: Claude could use curl and Node, but an ordinary npm installation was outside its frozen permissions. Both Codex buyers used the new report tool; that did not establish access in both hosts.

A new schema 6 plan may explicitly set `package_access: true`. This is accepted only for directed cells with the complete pinned reporting runtime already declared in `recipient.verifier`. The version comes from that existing pin. Unbranded discovery and older plans gain no package-specific prompt or permission.

The prompt and Claude allowlist share one exact standalone install command: the pinned public npm package, public registry, session scratch prefix/cache, and disabled install scripts. There is no wildcard npm permission. Both hosts receive the same command. The offline recipient remains offline and receives no installation permission. Native host policy can still refuse an invocation; only a real qualification can establish that it works.

Qualification keeps the original public-byte retention and randomized signature checks, then requires a fresh synthetic signed snapshot to be verified by the installed CLI into a saved Markdown report. The host retains the original, report and all pinned runtime files. The controller checks every runtime hash, visible successful standalone install and CLI invocations, the original fixture, complete capture, and exact report reproduction using the frozen controller CLI. A generic signature check, help screen, fabricated report or printed command does not satisfy the package gate.

This is explicit directed tool qualification, not package discovery, general package security, issuer trust or a buyer result. The fixed synthetic dates are fixture fields, not a freshness verdict. No merchant original is supplied by the controller. Buyer budgets, one-attempt policy, zero spend and the recipient protocol remain unchanged. The instrument includes the new helper in its frozen source inventory, so changing it after qualification prevents acquisition.

Tests cover the missing permission, illegal unbranded opt-in, missing reporting pin, incomplete capture, missing/altered modules, forged report, wrong fixture, absent/refused/echoed/compound install and absent CLI execution. The permission/prompt controls and the generic-check substitution control were observed failing against the prior implementation. The [September 30 native qualification](../research/package-access-qualification-2026-09-30/REPORT.md) is recorded separately: Codex passed, Claude voluntarily declined the package step, and the offline capability check passed. No buyer cohort launched; no earlier attempt is retried or rescored. An allowed command is not proof a model will choose to run it, and a model-reported denial is not proof of a host permission refusal.

# Recipient draft identifiers — October 1

The [bounded-review cohort](../research/bounded-source-review-buyer-2026-10-01/REPORT.md) retained a valid signature and correct generated output, followed by a recipient final that mistyped the signed-message digest as 62 hexadecimal characters. The existing instruction to cite the generated report did not prevent a later transcription error. The error is in the final text, not the signature.

Source version 1.11.0 adds an optional `verify-source --check-identifiers SAVED_DRAFT` check. The caller selects the original, key and any exact subject as before. The command re-verifies those bytes locally and compares whole long hexadecimal tokens in the saved draft against the identifiers computed or used in that verification. It never trusts a saved report as the reference, rewrites a draft, fetches anything or treats a match as proof of prose correctness.

The reference set is the original-file hash, signed-message hash, supplied public key and verified signature. Optional saved challenge headers add their computed file and address hashes; those unsigned inputs remain unsigned. Invalid signature verification leaves all candidate comparisons unchecked. Existing verification exits retain precedence; the optional check adds exit 4 for unrecognized candidates or no candidates. An unrecognized value can be a legitimate identifier outside the selected reference set, so the result asks for review rather than declaring it false.

Coverage is deliberately mechanical: whole ASCII hexadecimal tokens with at least 48 digits, optionally prefixed `0x`. Shorter hashes, split identifiers, addresses, non-hex values, labels, attribution, dates, negation and the surrounding prose are not assessed. Swapping two correct identifiers can pass this check. The output binds to the saved draft hash; it cannot cover a later final answer that changes those bytes. This addresses the witnessed transcription failure only when someone actually checks the draft before sharing it.

Input is capped at 128 KiB or the smaller caller byte limit and must decode as UTF-8. Every candidate is checked, but only 32 token readings are displayed; longer-than-128-digit values are counted without being printed. Reference aliases are capped at four displayed names per reading. Every omission is counted. The option cannot accompany `--report-out`, whose compact receipt would conceal the new check result. Existing commands without the option and their generated reports retain their behavior.

[Controller replay](../research/draft-identifier-check-2026-10-01/controller-replay.json) extracts the original final text from its hash-checked native event. The check recognizes the correct original-file hash and flags the recorded shortened digest, while the underlying signature still verifies. Original bytes and scores remain unchanged. This is an offline software replay, not a new native run, qualification or claim that recipients will use the option.

Publication and clean-install readback remain gates after normal PR/CI. The public buyer guide and frozen recipient prompts are unchanged. A future native experiment must explicitly freeze any added draft-saving/checking step, qualify it within the existing budget and preserve the unchanged final text plus the checked draft so later drift remains observable. No new cohort is launched by this change. Interpretation failures beyond lexical identifiers, merchant acceptance and platform acceptance remain open.

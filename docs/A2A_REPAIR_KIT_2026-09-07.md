# A2A repair-kit pilot — 2026-09-07

Authorized by the keeper after discussing a personalized repair report,
runnable regression tests, a signed recheck and a bounded watch:
“okay lets do all of it then nice”. Demand tag: keeper request / desk
reasoning. No paid customer demand is claimed. The $49 price is a pilot
hypothesis; the shelf derives it from `A2A_PRICE_USDC`.

## What is built

- `/a2a-desk`: browser card-check form, setup instructions and purchase path.
- `/a2a-desk.json`: the same proposition and money sentence, complete request
  examples, error meanings, operator authorization file, scope and limits.
- `POST /api/a2a/check` and MCP `check_a2a_card`: the same free, unsigned
  card check. GET documents it. One shared, atomic admission/free budget.
- `a2a_repair_kit`: one paid item through the existing browser, HTTP, MCP,
  payment verification, fulfillment and certificate machinery.
- `/samples/a2a-repair-kit.json`: unsigned specimen, produced by the actual
  instrument over constructed responses without contacting any host.
- `/api/a2a/runner.mjs`: downloadable Node 22+ runner, built from the same
  instrument as the Worker. CI refuses stale generated bytes. Exit 0 only
  when all applicable listed checks were observed and passed, 1 on failed
  checks, 2 on observation gaps, refusal or instrument failure.
- `/api/a2a/kits/{kit_id}`: permanent original report, suggested fixes, recheck
  and seven-day card-watch history. HTML for a browser, JSON for an agent.
- `POST /api/a2a/kits/{kit_id}/recheck`: one buyer-triggered recheck within
  30 days. The token is returned only in the purchase delivery. Repeated
  calls return the saved result. An interrupted execution is a visible gap;
  it is never silently retried after an uncertain task execution.

The initial signature covers the watch and recheck dates and kit ID.
Subsequent observations bind the kit, baseline hash and (for watch passes)
scheduled slot. Repair suggestions remain outside the observation signature.
They are not source-inspected patches and are never applied automatically.

Implementation help is a separate quote, requested with kit ID, public
repository URL, stack and scope. Initial guidance covers Hono/Workers.
No repository changes, other-stack expertise, completion guarantee or human
capacity are sold by this automated kit. A future commissioned patch must
identify store authorship when reporting its recheck.

## Supported observation

The official pinned A2A 0.3.0 schema validates cards and successful Task or
Message responses. Runtime tests exercise an operator-supplied new user
message, immediate task retrieval, terminal cancellation, malformed JSON,
null and invalid trailing parts, and an unknown task ID. Message responses
legitimately have no Task lifecycle. A valid application error leaves
successful execution unobserved. A running task is never canceled or
polled without bounds. No unsupported version receives a conformance pass.

The report states streaming, push, authentication, files, extended cards,
long-running lifecycle, application correctness and other transports as gaps.
The daily watch reads only the card. Runtime tests occur at purchase and
recheck, not on a timer. Missing slots are derived by slot identity rather
than subtracting a possibly duplicated row count from elapsed days.

## Operator permission and data

Runtime permission is a fixed JSON file at
`/.well-known/scvd-a2a-audit.json` on the card origin, naming that card and
the same-origin endpoint, with explicit audit, negative-test and repeat-safe
consent. It supplies a schema-valid new user Message and a bounded expiry.
It is read before purchase eligibility and again before execution/recheck.
The customer cannot supply an arbitrary payload through our checkout.

Only public test data belongs in this file: a broken endpoint might execute
the valid prefix of a malformed request. Public HTTPS, default ports, no
credentials, query or fragment, internal names or private address literals.
Redirects are not followed. Every fetch and body read is bounded; DNS pinning
is not claimed. Body and fixture limits are defined in the instrument and
published in the contract. Third-party response text is data and escaped in
HTML. No shell command or executable content is generated from that text.

Anyone holding the unguessable report link can read the bounded exchanges.
The link is not a secret vault. The recheck token is separately stored and
omitted from readable records. The existing purchase recovery path retains
the original delivery, including the token, for the buyer.

The existing item metrics and verification funnel include the new item.

## Release and verification

This feature adds the SQLite Durable Object class `A2AKitStore`, binding
`A2A_KITS`, migration `v4-a2a-kits`. The normal reviewed main deployment must
apply the migration; a preview version is not evidence it has been applied.
The doors Worker forwards targeted kit requests to the store; it still
answers the bare price request itself.

The boundary tests cover permission, private URLs, malformed responses,
missed reads, schema failures, byte ceilings, signature tampering, payment
refusal without settlement, immediate report reads, concurrent rechecks,
expiry, finite watch behavior and its atomic budget. The actual downloadable
runner is exercised against offline fixtures. Six regressions were witnessed
red after temporarily removing the desk route and key validation checks;
those source changes were then restored.

Primary reads are recorded in `docs/SPEC_READS.md` under this date.
Release PR: [#563](https://github.com/seancrecord/scvd-general-store-repo/pull/563),
`codex/a2a-repair-kit`. Typecheck, both Worker bundles,
download freshness and executable-runner tests, browser payment bridges,
package checks, scalability audit and claims register passed. The existing
A2A schema/lifecycle gate passed 31 tests.

The full local run covered 578 files and found one operation-ID mismatch
between the new checker and OpenAPI; the route now derives the ID through
the existing document builder. Its follow-up full run passed 577 files /
6,445 tests (one existing skip), but one Worker pool process timed out
before starting, so that run is not claimed as a clean full-suite pass.
The corrected checker and final A2A files passed 52 tests; the actual
download passed its four executable tests and its byte-freshness check.
Clean CI is the full-suite merge gate. No timeouts or assertions were relaxed.

Browser review exercised the desk and its free-check form, the specimen,
the item page and actual WebMCP registration. Paid delivery, signatures,
rechecks and the finite watch are verified with mocked settlement and
injected clocks. No live $49 purchase or elapsed seven-day history is
claimed by this release.

# Package source review before execution — September 30

The [closed package-access qualification](../research/package-access-qualification-2026-09-30/REPORT.md) established an installed-report pass in Codex and a voluntary refusal in Claude. Claude did not attempt npm. Its stated concern was executing unreviewed code; its self-written `commands_denied` field incorrectly named npm. The trace and prior outcome remain unchanged.

A separate directed plan can now opt into `package_review: {"source_commit": "<full forty-character commit>"}` alongside `package_access: true`. No existing plan gains this condition silently. The source repository and directory come from the hash-pinned package manifest; runtime filenames and hashes come from the existing verifier pin. Mutable branches and malformed or additional condition fields are refused. The controller must first read those immutable public source files and check they match the published package, then freeze that evidence with the new plan. A chosen source commit is not itself an npm provenance attestation.

The new prompt provides the immutable public source URLs, destinations and hashes. The agent can fetch with its existing curl/Node permissions, then run a local inspection command that reads and displays the files as text without importing them. Hash mismatches, oversized files and paths escaping the workspace stop that command. This is a convenient inspection path, not a general sandbox or a proof of package safety.

The agent records `evidence/package-review.json` with `decision` (`proceed` or `decline`) and its own nonempty `reason`. Declining inspection or execution is permitted. A retained refusal is recorded separately from observed host command denials and leaves package qualification incomplete. A refusal receipt accompanied by an observed package command is reported as a conflicting record; it cannot qualify.

For a proceeding qualification, the controller requires all retained source hashes to match and a visible successful standalone inspection before the first recognized install/CLI attempt. The original installed-runtime hashes, generated-report reproduction, generic signature checks, timing limits and one-attempt policy still apply. A report alone cannot substitute for review. The receipt is self-reported; command order does not prove comprehension, the time the assessment was written, or the absence of hidden execution. Source equality does not establish independent issuer identity, verified registry provenance or safety.

The public registry metadata URL is provided as data, without claiming its linked attestation was verified by the agent. No broader npm permission, online recipient, credentials or payment is introduced. Unbranded experiments and old package-only prompts remain unchanged. A new buyer cohort still requires every online host and the offline recipient to qualify; source-review refusal does not relax that gate.

The three initial controls were observed failing before implementation: invalid review conditions were accepted, installation alone could qualify the review plan, and the prompt omitted review/decision instructions. Additional controls exercise the actual inspection command, retained-byte tampering, missing decisions, denied/missing/late/echoed inspection, quoted shell invocation, explicit refusal and conflicting execution. A source-review native experiment must be recorded separately; implementation success is not buyer acceptance or evidence that the new condition changes a model's decision.
